## 关键实现点

### 1. 运行期权限边界（F-01）

- `agent.WithRunAdmin(ctx, false)` 由任务/会话创建者角色决定，贯穿 planner、worker、
  mainagent、自定义执行器、触发器会话与 Finding 派发会话。
- 非管理员运行：
  - 摘除 `Bash/Read/LS/Glob/Grep/Write/Edit/job_start/shell_*`；
  - 摘除平台高危工具（自定义工具、MCP、skill、删资产）；
  - 摘除 `mcp__*` 与 `command/script` 类自定义工具。
- `spawn_task` 子任务、Finding 派发会话、触发器会话继承父任务 `created_by`，
  不再以空创建者被当作系统任务。
- JWT 现在必须携带 `jti` 且对应 `auth_sessions` 中未过期的记录。
  仅拿到 `jwt.key` 无法再离线伪造管理员。

### 2. 流量证据与审批控制面（F-02/F-06）

- 新权限 `traffic:delete`、`intercept:approve`。
- 路由映射按方法区分：`DELETE /api/traffic*` 需要 `traffic:delete`；
  `/api/intercept/pending/{id}/decide` 需要 `intercept:approve`；
  规则 CRUD、`tool-config`、`judge`、任务级拦截规则写操作需要 `intercept:write`。
- operator 不再拥有 `intercept:write`，无法单方面停用内置规则或把 judge 失败动作改为 allow。

### 3. SSRF 与上传回放（F-03/F-04/F-12）

- ScopeSentry 数据源 URL 在写入时校验 scheme/host，拒绝回环/链路本地/组播；
  `mcphttp` 在拨号阶段再次校验，覆盖 DNS 重绑定。
- `sync/scopesentry/*` 不再把上游响应体片段拼进 API 错误。
- 附件 `Kind` 与扩展名/MIME 交叉校验；只有 png/jpeg/gif/webp/bmp/avif/ico 可 inline。
- 知识库上传增加请求体硬上限。

### 4. 密钥与部署（F-07/F-08/F-09/F-11/F-14）

- 服务初始化完成后 `agent.ScrubSensitiveEnv()` 删除 DSN、`*_API_KEY`、`*_TOKEN`、
  `*_SECRET`、`*PASSWORD*` 等变量；LLM 兜底配置使用启动时快照。
- Docker 镜像新增非 root 用户；hostd 仍以 root 运行但只通过 `0660` 属组 socket 暴露。
- 前端会话改为 HttpOnly Cookie；`localStorage` 只保留用户名展示信息。
- 上传的 Release 摘要/校验和默认强制；自更新可选 Ed25519 独立签名。

## 残余风险与运维要求

1. **F-14**：未配置 `KAIYANG_UPDATE_PUBKEY` 时，自更新仍信任 GitHub Release 的同源
   `SHA256SUMS`。生产发布建议生成 Ed25519 密钥对，公钥注入部署环境，私钥只放 CI Secret，
   并在 Release 中附 `SHA256SUMS.sig`。
2. **F-08**：hostd 默认要求校验源；上游 Release 既无 asset digest 又无 SHA256SUMS 时
   会安装失败。确认上游可信后可临时设置 `KAIYANG_HOSTD_ALLOW_UNVERIFIED=1`，不建议长期开启。
3. **HTTP MCP**：默认拒绝回环/链路本地。若确需本机 HTTP MCP，设置
   `KAIYANG_MCP_ALLOW_LOCAL=1`，并自行保证该端口不对不可信方开放。
4. **环境变量**：`FOFA_KEY` 等密钥不再从进程环境继承给 Agent 子进程；依赖环境变量的
   MCP 需在 MCP 配置的 `env` 中显式提供。
5. **升级影响**：旧 JWT 没有服务端会话记录，升级后所有用户需要重新登录一次。
